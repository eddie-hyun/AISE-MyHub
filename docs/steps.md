## Step 1 — 백엔드 ↔ Supabase 연결

*8개 단계 · [문서 전체 보기](step1_backend_supabase.md)*

- **1-1. 이 단계의 목표** — 파이썬 서버가 Supabase DB와 실제로 통신하는지 눈으로 확인하는 것이 목표
- **1-2. 완성된 모습** — `/health` 호출 시 DB 버전 정보가 JSON으로 응답되는 최종 결과를 먼저 확인
- **1-3. 파일 구조와 작업 위치** — backend 폴더 구조와 `.env` / `.env.example`을 나누는 이유를 정리
- **1-4. 처음부터 따라 하기** — Supabase 프로젝트 생성부터 서버 실행까지 6단계로 직접 따라 구현. 1단계(프로젝트 뼈대)는 AI 코딩 에이전트에게 준 프롬프트로 진행

  **예제 프롬프트**
  ```
  `backend` 디렉토리에 다음 기술스택을 갖는 파이썬 백엔드 프로젝트 초기화.

  * python
  * fastapi
  * supabase (postgresql, session spooler) + psycopg 동기호출


  supabase 데이터베이스에 접속하여 연결된 데이터베이스의 상태와 버전을 json으로 응답하는 /health 엔드포인트를 미니멀하게 구현.
  구현체는 main.py 파일 하나로 통합.
  필요한 conn info, api secret 등은 .env 파일에 만들어서 서버가 env로부터 로드하도록 함. (.env.example로 예제를 제공해야 함)
  필요한 디펜던시는 pip requirements.txt 파일로 정리.
  ```

- **1-5. 코드 전체** — 완성된 `backend/main.py` 전체 코드를 한 번에 수록
- **1-6. 보안 체크리스트** — `.env` 노출 방지 등 비밀번호·접속정보 관리 체크리스트 정리
- **1-7. 지금까지 배운 개념 정리** — venv, FastAPI, uvicorn, anon key 등 핵심 용어를 표로 요약

## Step 3 — 화면 붙이기 (React + TypeScript)

*10개 단계 · [문서 전체 보기](step3_react_frontend.md)*

- **3-1. 이 단계의 목표** — JSON 데이터를 사람이 보는 이력서 페이지로 만드는 것이 목표
- **3-2. 시작 전 확인** — Node.js와 npm이 설치되어 있는지 버전을 먼저 확인
- **3-3. ① React 프로젝트 만들기** — Vite로 React + TypeScript 프론트엔드 프로젝트를 새로 생성. 이후 남은 네 조각(②~⑤)은 AI 코딩 에이전트에게 준 프롬프트로 진행

  **예제 프롬프트**
  ```
  `frontend` 디렉토리에 다음 기술스택을 갖는 프론트엔드 프로젝트 초기화.

  * Typescript 기반 React
  * Vite 빌드, 개발서버

  backend(FastAPI, 8080번 포트)가 제공하는 프로필 데이터를 사람이 보는 이력서 화면으로 표시하는 기능을 미니멀하게 구현.

  * 개발 중에는 Vite 프록시로 `/api`로 시작하는 요청을 BE에 그대로 전달.
  * BE 응답 스키마는 Pydantic DTO로 스키마를 명시됨. 이 OpenAPI 스펙(`/openapi.json`)에서 TS 타입을 자동 생성하고 프론트엔드에서는 이 타입만을 이용하여야 함.
  * BE가 데이터베이스에서 읽어와서 제공하는 이름, 한 줄 소개, 상세 소개, 마지막 수정 시각을 화면에 표시.
  ```

- **3-4. ② 프록시로 백엔드 연결하기** — Vite 프록시로 `/api` 요청을 백엔드로 넘겨 CORS 없이 연결
- **3-5. ③ Pydantic DTO와 타입 자동 생성** — Pydantic DTO로 OpenAPI 스펙을 만들고 TS 타입을 자동 생성해 사용
- **3-6. ④ 이력서답게 다듬기** — 한글 줄바꿈, 다크모드, 인쇄 CSS 등으로 이력서 화면을 다듬음
- **3-7. ⑤ `openapi-fetch`** — `openapi-fetch`를 도입해 주소 오타까지 컴파일 시점에 잡아내게 개선
- **3-8. 코드 전체** — 완성된 백엔드·프론트엔드 코드 전체를 한 번에 수록
- **3-9. 이번에 배운 개념** — Vite, HMR, 프록시, DTO, `useEffect` 등 핵심 용어를 표로 요약
- **3-10. 다음 단계 (Step 4)** — 내가 직접 로그인해서 이력서를 수정하는 다음 목표를 예고

## Step 4 — 내가 로그인해서 수정하기

*7개 단계 · [문서 전체 보기](step4_login_and_edit.md)*

- **4-1. 이 단계의 목표** — Supabase 대시보드 없이 웹 화면에서 직접 이력서를 고치는 것이 목표. AI 코딩 에이전트에게 준 프롬프트로 진행

  **예제 프롬프트**
  ```
  Supabase에 있는 데이터(profile) 수정을 FE 웹 페이지를 통해서 할 수 있도록 BE와 FE를 수정.

  * BE: 비밀번호로 세션 기반 로그인 구현. 관리자 전용 기능은 로그인 상태에서만 가능.
    * 인증 엔드포인트 구현: 로그인, 로그인 상태 확인, 로그아웃
    * 프로필 수정 엔드포인트 (PUT).
    * id, 수정 시각은 서버가 데이터 수정 시 정하도록 함.

  * FE: 별도 편집 페이지 없이, 보고 있던 이력서 화면 그대로에서 로그인 후 in-place edit.
    * 로그인 성공하면 프로필 페이지 자체가 편집 모드 전환. 저장, 로그아웃 기능 추가.
    * 로그인이 풀린 상태로 저장을 시도하면 로그인 화면으로 안내.

  기존 화면(비로그인 상태의 프로필 보기)은 그대로 동작해야 함.
  ```

- **4-2. 완성된 모습** — 로그인하면 같은 화면이 그대로 제자리 편집 모드로 바뀌는 결과를 확인
- **4-3. ① 백엔드 — 로그인과 수정 엔드포인트** — 세션 로그인 3종 엔드포인트와 PUT `/api/profile` 수정 엔드포인트 구현
- **4-4. ② 프론트엔드 — 제자리 편집** — 로그인 상태에 따라 읽기 화면과 편집 화면을 전환하는 로직 구현
- **4-5. 코드 전체** — 완성된 백엔드·프론트엔드 코드 전체를 한 번에 수록
- **4-6. 이번에 배운 개념** — 세션, `SessionMiddleware`, `Depends`, `RETURNING` 등 핵심 용어 요약
- **4-7. 다음 단계 (Step 5)** — raw SQL 대신 ORM으로 데이터베이스를 다루는 다음 목표를 예고

## Step 5 — ORM 도입 (SQLAlchemy)

*8개 단계 · [문서 전체 보기](step5_orm_sqlalchemy.md)*

- **5-1. 이 단계의 목표** — raw SQL 대신 파이썬 클래스로 데이터베이스를 다루게 만드는 것이 목표. AI 코딩 에이전트에게 준 프롬프트로 진행

  **예제 프롬프트**
  ```
  이제는 SQLAlchemy를 도입하여 데이터 접근을 오브젝트 방식으로 변경할 것임.

  * 마이그레이션과 스키마 관리는 불필요함.
  * 현재의 테이블 정의를 파이썬 엔티티 클래스를 만들어서 이전.
  * 서버가 시작할 때 엔티티 기준으로 없는 테이블은 자동 생성하고 새 테이블은 비어있으니 초기 데이터 1건을 insert.
  * 기존에 구현된 기능들의 데이터베이스 접근을 raw SQL 대신 ORM 호출로 교체.
  * API의 주소와 응답 모양(OpenAPI 스펙)은 그대로 둠.
  * db.py, models.py, schemas.py 로 구현 내용을 적절히 분리하여야 함.
  ```

- **5-2. ORM 이 뭐고, 왜 쓰나** — ORM 개념을 소개하고 얻는 것과 잃는 것을 솔직하게 비교
- **5-3. ① 설치 · 파일 분리 · 엔티티 정의** — SQLAlchemy를 설치하고 `db.py` / `models.py` / `schemas.py`로 파일 분리
- **5-4. ② 테이블 자동 생성과 seed** — 서버 시작 시 테이블을 자동 생성하고 없으면 초기 데이터 1건을 입력
- **5-5. ③ 엔드포인트를 ORM 으로** — 엔드포인트의 raw SQL 쿼리를 전부 ORM 호출로 교체
- **5-6. ④ 정리** — 최종 파일 구조를 정리하고 프론트엔드가 영향받지 않았음을 확인
- **5-7. 이번에 배운 개념** — 엔티티, 세션, 더티 트래킹 등 ORM 핵심 용어를 표로 요약
- **5-8. 여기까지의 여정** — Step 1~5 전체 여정을 되짚고 다음 확장 방향을 제시하며 마무리
